# Plan 0036：模拟赛车爱好者成长与体验路线图

> 状态：提案；尚未承诺实施  
> 更新时间：2026-11-05  
> 范围：在现有 LapWing / Racing Memory 能力之上，探索如何持续帮助模拟赛车爱好者进步、获得回忆并建立关系  
> 前置：Plan 0031 Racing Memory、Plan 0033 比赛自动化流水线、Plan 0034 平台模块化、Plan 0035 F1 UDP adapter  
> 非目标：本计划不替代 Plan 0035 的 F1 25 接入工作，不修改其协议、fixture 或 Windows lifecycle 实现

## 1. 问题与方向

当前项目已经不是单一遥测查看器：它能导入多种遥测、分析圈速和分段、比较参考圈、
管理 setup 历史、同步视频、导出叠加层和 MP4、生成 Racing Memory、输出成绩单和规则式
驾驶建议，并通过分享、排行榜和车手主页提供可选社区能力。

F1 25 adapter 是扩大游戏覆盖面的一条必要路线，但不应让产品路线图退化成一串游戏名称。
更重要的问题是：

> 同一个玩家使用三个月后，除了保存更多录像，是否更清楚自己在如何进步、下一次该练什么，
> 以及是否更愿意回来驾驶、比赛或和朋友分享？

建议的长期定位不是泛化的“AI 遥测教练”，而是：

> **面向普通爱好者的个人赛车成长档案：每场驾驶自动留下回忆，帮助理解下一次练什么，
> 并把个人成长延伸为朋友、俱乐部、教练或门店之间的关系。**

这是一组产品假设，必须通过真实用户试验验证；不是已证实的市场需求或已承诺功能。

## 3. 已知边界与设计约束

后续功能必须诚实处理以下限制，不能把推测包装成事实。

### 3.1 精彩时刻目前是规则检测，不是完整比赛理解

当前事件包括最佳完整圈、合法排名改善、incident 增量和记录结束。排名改善并不必然是
主动超车；记录结束并不保证正式方格旗。未来的比赛技艺分析、自动叙事和裁判类功能
必须区分直接观测、规则推测与用户确认，不能仅凭个人遥测自动判责。

### 3.2 驾驶建议目前是确定性比较，而非个性化教练

现有建议以同一会话最快完整圈为参考，利用时间损失、速度、制动和油门差异生成证据。
它不能在缺少油量、胎况、交通、天气、辅助或车辆状态时保证因果归因。产品文案应说
“值得检查的机会”，而不应说“这一定是原因”。

### 3.3 跨游戏能力必须 capability-gated

canonical telemetry 支持 `geo`、`world` 与 `track-progress` 空间模型。无 GPS 游戏不能
伪造经纬度；依赖地图几何的功能需要实现 world/track-progress 版本或明确隐藏。
跨游戏记录可以统一展示，但不同游戏、车辆、辅助设置与版本之间的成绩不可默认可比。

### 3.4 自动化可靠性优先于功能堆叠

Windows + 游戏 + OBS 的端到端发布验收仍需要在真实目标机器完成。采集失败、录像不覆盖
事件、时间轴低置信度、设备设定不一致等问题必须可诊断、可恢复，并且对普通用户可理解。

## 4. 产品路线：五个方向

以下方向不是顺序固定的 backlog；每项都应先以最小闭环测试用户行为。

### A. 从赛后报告到有效训练

#### A1. 短时训练助手：“只有 20 分钟，今天练什么？”

用户输入可用时间、车辆/赛道和目标（速度、稳定或比赛准备），系统只给一个清晰练习任务：

- 选择一个弱项而不是罗列全部问题；
- 说明目标、可观察的证据与完成标准；
- 训练结束后判定是否完成；
- 下次自动复测或建议继续同一任务。

例：不追求 PB，连续五圈练习某弯的制动释放，并检查制动时长和出弯油门是否更一致。

最小版本：限制在同车同赛道；从规则式 insight 中选一项生成训练卡；下一场复测。

#### A2. 弯道成长护照

把赛道的关键区间变成长期记录单元，展示：

- 近期制动点/制动时长分布；
- 最低速度、出弯速度与时间损失；
- 是否为重复弱项；
- 哪次练习带来了变化；
- 对应视频、笔记与用户/教练标注。

最小版本：让用户在赛道上手动定义 3–5 个练习区间；不要求自动识别全部弯名。

#### A3. 和过去的自己比赛

把趋势从“偶然最快圈”扩展为：

- PB；
- 常规有效圈的中心水平；
- 稳定性；
- 连续干净圈；
- 特定区间的改善；
- 过去与现在的同步视频。

最小版本：仅比较同车、同赛道、明确可比条件的跨会话数据；不能直接将不同游戏圈速排成统一榜单。

#### A4. 有证据的 AI 复盘

自然语言只负责解释和组织，事实必须由确定性分析提供。每条结论应可回到：

1. 圈次/时间/赛道区间；
2. 当前与参考数据；
3. 同步视频；
4. 不确定性；
5. 下一次验证方法。

最小版本：把已计算的 analytics、DrivingInsight 和视频片段整理为结构化上下文，再生成解释。
禁止让模型直接对全部原始遥测做无证据的因果判断。

### B. 从刷圈到比赛能力

#### B1. 比赛准备度

用户可建立一份可解释的赛前检查表：

- 连续干净圈；
- 目标节奏及稳定性；
- 起步/进站练习；
- 连续驾驶后的节奏保持；
- 指定赛道与车辆的练习完成度。

输出应说明未满足的具体条件，而非给出神秘综合分或安全认证。

最小版本：用户设定目标，系统根据当前 session 数据逐项验证。

#### B2. 比赛技艺复盘

围绕攻防、跟车、避险和失误恢复做赛后标注：

- 为什么此处失去位置；
- 防守后是否损失节奏；
- 跟车时的重复问题；
- 哪些避险或恢复值得保留。

最小版本：用户先标记片段和描述，系统附加时间轴、位置、速度和可用的比赛状态。
未来如有可靠对手数据，再增量提供相对距离或事件分类；首版不做自动判责。

#### B3. 耐力赛与车队助手

服务小车队的训练与交接：

- 车手长距离节奏与一致性；
- 训练分工；
- setup 备注；
- 分段驾驶总结；
- 换人交接卡；
- 赛后各车手自动汇总。

最小版本：共享训练记录、手动交接卡和可分享的 session 摘要。油量、胎耗和策略必须有可靠游戏字段后再做自动判断。

### C. 从数据到车辆、设备和实验

#### C1. Setup 实验室

当前 setup revision 已能够关联会话。下一步是指导可复核实验：

- 一次仅改变一个参数或一组明确相关参数；
- 保存改动前后的测试组；
- 记录油量、轮胎、天气、辅助与主观感受；
- 比较圈速分布、稳定性与关键区间；
- 以样本限制说明结论强度。

期望输出：“当前样本下 B 更稳定，但不足以证明单圈一定更快”，而非“推荐神奇 setup”。

最小版本：A/B 实验向导与两组 session 对比。

#### C2. 设备基线与输入体检

记录和发现会拖累体验的输入问题：

- 松开踏板后的残余输入；
- 是否可到达满量程；
- 输入抖动；
- 转向中心偏移；
- 游戏/设备设置的变化；
- 设备更换前后的驾驶表现。

最小版本：静态输入测试页 + 用户确认的配置快照。必须区分设备原始输入和游戏处理后通道，不能轻率诊断硬件故障。

### D. 从文件输出到值得保存的体验

#### D1. 自动赛事导演

从按分数拼接事件窗口，进化为用户可选择的叙事模板：

- PB 突破；
- 逆风比赛；
- 与朋友的攻防；
- 第一次练习到突破；
- 失误后的恢复。

叙事由“目标 → 困难 → 关键尝试 → 结果”组成，而非片段堆叠。

最小版本：先做“PB 突破”和“过去 vs 现在”两种模板，允许用户确认事件含义。PB 视频应展示改善发生的位置，而不仅显示圈末成绩。

#### D2. 个人赛车生涯

建立不只服务最快玩家的长期身份：

- 第一场比赛、第一场无事故比赛、首次领奖台；
- 掌握一条赛道、尝试一类车型；
- 与朋友共同参与的活动；
- 年度回忆与自定义里程碑。

最小版本：个人时间线 + 用户确认的里程碑 + 年度回忆页。用户应能选择重视速度、干净驾驶、稳定、探索或团队贡献，而不是只有总积分。

#### D3. 异步好友挑战

优先服务熟人小圈子，而非立即做全球匹配：

- 同车同赛道的周挑战；
- 连续五圈稳定性挑战；
- 改善自己最弱区间的挑战；
- 与朋友参考圈的同步对比。

最小版本：邀请链接、明确规则、结果卡。必须显示设备、辅助、版本和环境；未验证条件只能作为友好挑战，不应标为严格认证成绩。

#### D4. 可学习的单圈分享

分享一圈时附带：

- 遥测与同步视频；
- 三个重点区间；
- 作者语音或文字说明；
- 车辆、赛道、条件；
- 适合复现的练习任务。

最小版本：在既有分享能力上加区间注释和讲解；优先支持朋友互教、俱乐部教学和真人教练。

### E. 从个人工具到专业服务

#### E1. 教练工作台

增强真人教练，而不是先试图替代真人：

- 汇总近期训练；
- 标出重复问题与可回看的片段；
- 布置单一任务；
- 下次自动生成作业对照；
- 保存教练对自动建议的修订。

最小版本：一个教练、少量学员、训练任务与回看入口。这也是验证自动 insight 是否真正有用的高价值渠道。

#### E2. 门店—家庭成长护照

服务线下门店与家庭设备之间的连续训练：

- 在店里发现问题；
- 带走训练任务、视频、setup 和记录；
- 回家继续练；
- 下次到店无需重新建立背景。

最小版本：一个可导入/导出或可撤销授权的个人训练包。不要在首轮同时建设预约、收银、库存、完整会员和复杂段位。

#### E3. 驾驶情景练习库

按能力问题而不是赛道组织训练：

- 制动释放；
- 连续弯节奏；
- 低速弯出弯；
- 湿地平顺输入；
- 起步与进站；
- 长距离稳定性。

每项包含游戏内设置、练习目标、需要记录的数据、完成标准和前后对比方式。

最小版本：练习说明 + 赛后评估。自动载入场景或控制游戏只能在官方接口明确允许时再研究。

## 5. 探索性原型

这些方向适合小范围测试，不应在主线成熟前扩大投入。

| 原型 | 要验证的问题 |
| --- | --- |
| 遥测听觉化 | 不看复杂图表时，声音是否帮助理解制动/油门差异 |
| 安静教练模式 | 一组练习后的一句重点是否比持续提示更有效 |
| 回归驾驶模式 | 中断一段时间后，能否低压力地恢复个人基线 |
| 失败收藏夹 | 保存失误及后续解决过程，能否将挫败转为学习证据 |
| 跨游戏技能档案 | 哪些观察可跨游戏展示，哪些必须严格分开 |
| 面向非玩家的比赛摘要 | 是否能让亲友理解一场比赛发生了什么 |

## 6. 推荐实施顺序

不要同时推进全部方向。建议以三个相互复用的闭环开始。

### P0：训练卡与下次复测

**要证明：用户是否愿意因为一项明确建议而再练一次。**

闭环：

```text
一场 session → 一个有证据的问题 → 一个训练任务 → 下一场复测
```

初始指标：

- 训练卡打开率；
- 任务完成率；
- 7/30 天复测率；
- 用户确认“建议具体且有帮助”的比例；
- 条件可比的情况下，关键指标是否改善。

### P1：成长档案与过去/现在对比

**要证明：长期记录是否促成持续使用。**

先做同车同赛道的趋势、稳定性与同步视频。不要在证据不足时声称某次变化由产品建议造成。

初始指标：

- 历史记录回看率；
- 对比视频导出/保存率；
- 同赛道回归率；
- 用户手动确认里程碑的比例。

### P2：故事化 PB 视频

**要证明：自动内容是否值得保留或分享。**

先把一个模板做好，衡量：

- 自动选择片段的保留率；
- 用户修改次数和修改原因；
- 导出与实际分享率；
- 分享后是否带来回流或下一次驾驶。

## 7. 与 F1 25 工作并行的边界

| 工作线 | 当前目标 | 原则 |
| --- | --- | --- |
| F1 adapter | 原始 UDP capture、版本 decoder、canonical mapping、Windows/OBS 实机验收 | fixture-first；不猜字段；真实数据优先 |
| 玩家成长 | 训练卡、跨会话趋势、故事模板、用户验证 | 先复用 iRacing 现有数据，不等待 F1 完成 |
| 验证线 | 真实爱好者/教练/车队试用 | 测行为与效果，不只收集“看起来很酷”的反馈 |

成长功能可首先建立在 iRacing 的成熟数据上。若要修改 canonical telemetry、capability
或 capture 契约，必须与 F1 adapter 工作协调，避免并行改变底层接口。

## 8. 所有方向共用的基础能力

无论选哪一条产品路线，建议先形成以下横向机制：

1. **可比条件模型**：明确车辆、赛道/布局、游戏版本、辅助、天气、轮胎、油量和设备等；
   缺失时降级结论。
2. **证据等级**：UI 和导出中区分直接观测、规则推测、模型建议与用户/教练确认。
3. **失败可诊断性**：采集、视频覆盖、同步与导出失败都给出可执行恢复步骤。
4. **用户控制与隐私**：默认本地；明确每份遥测、视频、分享和教练协作数据的授权范围与撤销方式。
5. **效果评估埋点**：优先测训练复测、复访、导出/分享、人工修订和失败率，不将单一 PB 当作唯一成功指标。

## 9. 后续决策原则

- 不因为“接到数据”就假定能理解比赛、判责或控制游戏。
- 不因为“有 AI”就省略可验证的数据证据。
- 不因为“有排行榜”就假定会形成社区或复访。
- 不因为“内容可分享”就假定会产生收入。
- 先在少量真实爱好者、教练、车队或门店用户中验证一个循环，再扩大范围。

长期值得追求的体验是：

> 下班驾驶二十分钟，自动留下值得保存的回忆；知道这次进步了什么，也知道下次该练什么。
